Implement a module that realizes Conway's Game of Life on a 16x16 toroidal grid, where the grid wraps around at the edges to form a torus topology.

Module name:  
    TopModule

Input ports:
    clk: Clock signal for synchronous operation (active rising edge)
    load: Synchronous load control signal (active high) to initialize or override the game state
    data: 256-bit vector representing the initial or override state to be loaded into the grid

Output ports:
    q: 256-bit vector representing the current state of the 16x16 game grid, updated every clock cycle

Implementation:
    This module implements Conway's Game of Life cellular automaton on a 16x16 grid with toroidal boundary conditions. The 256-bit state vector is organized such that each consecutive 16-bit segment represents one row of the grid: bits 15 downto 0 represent row 0, bits 31 downto 16 represent row 1, and so forth up to row 15.

    The toroidal topology ensures that cells at the grid edges have neighbors that wrap around to the opposite edge. For instance, a cell at the top edge considers cells from the bottom edge as its upper neighbors, and a cell at the left edge considers cells from the right edge as its left neighbors. This wrapping applies to all eight neighboring positions around each cell.

    The module uses a padding strategy to simplify neighbor access. An internal padded representation extends the grid by replicating edge cells to the opposite sides, creating a virtual 18x18 structure where the outer rows and columns are copies of the wrapped edges. This allows straightforward indexing of all eight neighbors for each of the 256 cells without special-case boundary logic.

    On each rising clock edge, the module computes the next state for all cells in parallel according to the standard Conway's Game of Life rules:
    - A cell with zero or one neighbor becomes dead (0)
    - A cell with exactly two neighbors retains its current state
    - A cell with exactly three neighbors becomes alive (1)
    - A cell with four or more neighbors becomes dead (0)

    The neighbor count for each cell is computed by summing the states of its eight adjacent cells in the padded grid. The module then combines this neighbor count with the current cell state using a bitwise OR operation, masked to three bits. If this combined value equals three, the cell is set to alive; otherwise, it is set to dead. This logic elegantly captures the Game of Life rules in a compact expression.

    The load signal provides synchronous override capability. When load is asserted high at a clock edge, the entire grid state is replaced with the value present on the data input, allowing initialization or external intervention. This load operation takes priority and occurs after the normal game state update logic.

    The game advances by one generation every clock cycle, continuously updating the grid based on the cellular automaton rules, unless overridden by the load control.
